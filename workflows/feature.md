# Feature Workflow

Use when the user wants a new capability or meaningful change.

1. Understand the desired outcome.
2. Identify the project.
3. Inspect the current implementation and constraints.
4. Define acceptance criteria.
5. Choose architecture and implementation approach.
6. Implement the smallest coherent change.
7. Test the happy path and important edge cases.
8. Review security and regressions.
9. Update project context and documentation.
10. Report changed files, verification, and remaining risks.

For high-impact or destructive changes, obtain confirmation before execution when needed.
