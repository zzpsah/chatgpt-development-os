## Architecture decision

The next maturity gap was defined as **P17 Step Readiness & Authorization Orchestrator**, not another generic autonomy layer.

Canonical path under development:

`Human input → P15 Human Language Interpretation → Project Router / State Resolver → P16 Semantic Goal-to-Plan Compiler → P17 Step Readiness & Authorization Orchestrator → Development Task Controller → bounded runtime → Verification + Security → durable state`

P17 must never execute work or manufacture permission. Its job is only to decide whether one exact compiled plan step is currently eligible to proceed.

### 3. Added P17 normative contract

Added `core/step-readiness-authorization-orchestrator.md`.

Defined `DEVOS-STEP-READINESS-v1` with outcomes:

- `READY`
- `NEEDS_EVIDENCE`
- `NEEDS_APPROVAL`
- `BLOCKED`
- `STOP`

Required invariants include exact-step identity, fresh repository state, dependency completion, capability availability, step-bound authorization, Security Gate evidence when required, and an applicable verification path.

All outcomes preserve:

- `authority: UNCHANGED`
- `authorization: UNCHANGED`
- `execution: NONE`

### 4. Added executable P17 readiness evaluator

Added `tools/step-readiness-orchestrator.py`.

The evaluator binds readiness to:

- `DEVOS-GOAL-PLAN-v1` plan state;
- exact step id;
- compilation repository head;
- current repository head;
- completed dependencies;
- per-step capability evidence;
- per-step authorization evidence;
- per-step Security Gate evidence;
- verification requirement.

A compilation/current repository-head mismatch produces `STOP` rather than silently reusing a stale plan.

### 5. Added exact-step approval isolation

Authorization evidence is keyed by step id. Approval for another step does not satisfy an authorization-required step. This prevents approval leakage from prior work, lower-impact steps, or another session.
